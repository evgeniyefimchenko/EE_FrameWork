# Установщик проекта

Установщик помогает развернуть EE_FrameWork без ручной правки `inc/configuration.php`. Он собирает настройки сайта, проверяет окружение и базу данных, создаёт таблицы, подготавливает runtime-директории и показывает дальнейшие шаги для cron.

## Способы запуска

Web-мастер доступен по адресу:

```text
/install/
```

CLI-режим доступен из корня проекта:

```bash
php inc/cli.php install:status
php inc/cli.php install:run --site-host=example.com --site-author="Site owner" --site-email=mail@example.com --admin-email=mail@example.com --db-name=project_db --db-user=project_user --db-pass=secret
```

Если база данных и пользователь уже созданы, достаточно указать параметры подключения. Если установщик должен создать их сам, дополнительно укажите административный доступ к MySQL/MariaDB:

```bash
php inc/cli.php install:run \
  --site-host=example.com \
  --site-author="Site owner" \
  --site-email=mail@example.com \
  --admin-email=mail@example.com \
  --db-name=project_db \
  --db-user=project_user \
  --db-pass=secret \
  --create-database \
  --create-user \
  --db-admin-user=<admin-user> \
  --db-admin-pass=<admin-password>
```

## Настройки сайта

Установщик заполняет основные параметры проекта:

- домен и протокол сайта;
- название и описание сайта;
- владелец/автор;
- email сайта, администратора и поддержки;
- `ENV_PROTO_LANGUAGE`;
- `ENV_CONTENT_LANGS`;
- `ENV_BOOTSTRAP533_CDN`;
- `ENV_FONT_AWESOME_CDN`;
- юридические сведения оператора;
- пароли стартовых пользователей.

`ENV_PROTO_LANGUAGE` задаёт базовый язык прототипа и fallback-значение. `ENV_CONTENT_LANGS` задаёт языки контента, например `RU` или `RU,EN`.

CDN-флаги управляют только публичным проектом после установки. Сам установщик не подключает Bootstrap, Font Awesome или другие внешние библиотеки.

## База данных

Минимально нужны:

- host;
- имя базы данных;
- пользователь;
- пароль;
- префикс таблиц.

Префикс по умолчанию: `ee_`.

При включённых опциях создания БД установщик выполняет:

- создание базы данных, если её ещё нет;
- создание пользователя, если его ещё нет;
- выдачу прав на выбранную базу.

Административные данные MySQL/MariaDB используются только во время установки и не записываются в `inc/configuration.php`.

## Безопасность

После успешной установки мастер блокируется lock-файлом. Повторный запуск через web-интерфейс недоступен.

Повторная установка из CLI требует явного подтверждения:

```bash
--force --overwrite-config
```

Секреты не должны попадать в Git. Рабочий `inc/configuration.php` содержит параметры конкретного сайта и не предназначен для публикации. Для репозитория используется `inc/configuration.sample.php`.

Обычный запрос в приложение не разворачивает таблицы автоматически. Если схема БД не установлена, приложение сообщает об ошибке установки, а создание схемы выполняется только через установщик.

## Ход установки

Установщик выполняет шаги:

1. Проверяет PHP-версию и обязательные расширения.
2. Проверяет права на runtime-директории.
3. Проверяет подключение к базе данных.
4. Создаёт `inc/configuration.php` из шаблона.
5. Создаёт таблицы и стартовые данные.
6. Создаёт bootstrap-пользователей.
7. Запускает health-check.
8. Записывает lock-файл.
9. Показывает рекомендуемую cron-команду.

Рекомендуемая cron-команда:

```cron
* * * * * cd /path/to/site && php app/cron/run.php >/dev/null 2>&1
```

## Статус и диагностика

Статус установки доступен в CLI:

```bash
php inc/cli.php install:status
```

Web-мастер показывает progress bar и текущий шаг установки. Ошибки должны быть понятны администратору: что проверялось, почему это важно и что сделать дальше.

После установки допустим временный post-install diagnostic mode для проверки БД, прав на директории, cron и web-server rewrite. Перед публикацией сайта отладку нужно отключить, а production-конфигурация должна оставаться на `ENV_DEBUG=false`.
